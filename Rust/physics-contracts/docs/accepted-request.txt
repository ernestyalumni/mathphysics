Implement the first shared contract layer from the approved mathphysics Rust platform plan (F01). Use Rust for a typed library and a JSON CLI that validate book-item, assumption, convention and evidence metadata. The user approved starting the complete plan and spawning subagents on 2026-10-31.

The implementation MUST keep equation, exercise, prose, diagram, example, definition and theorem identifiers distinct, including when printed numbers match. It MUST require explicit source digests and locators, stated domains, assumption and convention references, and separate implementation and evidence states. It MUST reject unknown references, invalid hashes, malformed IDs, duplicate identifiers, missing sources, mismatched statement/operation links, unsupported schema versions and inconsistent numerical/formal evidence metadata. It MUST use bounded inputs and return structured invalid-input errors rather than panic or silently ignore unknown fields. It MUST NOT treat successful metadata validation as a mathematical proof, a verified source transcription, a successful computation, or a claim that any evidence artifact was replayed. The output MUST state that assurance boundary explicitly. Frontend work and existing symbolic engines are out of scope for this first unit. Core runtime MUST be Rust with no Python, C++, external CAS or model invocation required. Preserve existing mathphysics code and source corpora.

For example, srednicki:ch035:equation:35.1 and srednicki:ch035:exercise:35.1 are distinct valid IDs. A record referring to an undeclared assumption is invalid. A numerical evidence claim cannot be labeled a kernel-checked formal proof.
